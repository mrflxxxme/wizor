## Context

Probe-мониторинг (P5) и competitive gap (P6) работают над «целевыми промптами». P5 реализовал версионируемое **хранение** `prompt_sets`, но **происхождение** промптов не специфицировано нигде: кто и как их создаёт. В P9-онбординге есть строка «предложенные промпты» без механики. Для Tier-0 (аноним, no-auth, быстрый) промпты **обязаны** генерироваться полностью автоматически — пользователь ничего не вводит, кроме URL. Без определённой механики автономный `planner` P6/P7 упрётся в неспецифицированную зависимость.

## Decision

**Промпты авто-генерируются из контента сайта**, модуль `PromptSetGenerator`:

- **Вход:** crawl-данные P2 (`crawl_results`: тематика страниц, услуги/продукты, гео-сигналы, заголовки, entity-кандидаты).
- **Механика:** LLM-router (RU-default → GigaChat/YandexGPT, инвариант §6.6) генерирует `N≈10` промптов вида «где заказать <услуга> в <гео>», «лучший <продукт> для <задача>» — формулировки, по которым реальный пользователь спросил бы LLM и ожидал бы увидеть сайт в ответе.
- **Хранение:** результат — версионированный `prompt_set` (переиспользует схему P5); `prompt_set_version` привязывается к probe-прогонам (закрывает P5-deferred про binding, evidence для P8).
- **Реализация — в P6:** competitive gap (P6) — первый массовый потребитель промптов (нужны, чтобы найти цитируемых конкурентов). Генератор — отдельный модуль контекста `recommendations`/`probe`, вызывается и из Tier-0 оркестратора (P7), и из regular probe (P5 переиспользует при регулярном мониторинге).
- **Ручное управление — в P9:** онбординг-визард показывает авто-сгенерированные промпты, пользователь может редактировать/удалять/добавить свои; число промптов лимитировано тарифом (Starter < Pro < Business). Правка создаёт новую `prompt_set_version` (аудируемо).

## Consequences

- **Позитивно:** Tier-0 работает полностью автоматически (no-auth совместим); regular-мониторинг стартует с осмысленным набором без ручного ввода — снижает time-to-value.
- **Позитивно:** `prompt_set_version` binding закрывает P5-deferred (evidence-целостность для P8 verification).
- **Позитивно:** переиспользование одного генератора тремя потребителями (Tier-0/P6-gap/P5-probe) — ноль дублирования.
- **Компромисс:** качество авто-промптов зависит от качества crawl-данных и LLM — возможны нерелевантные промпты. Митигируется ручной правкой в P9 (лимит по тарифу) и версионированием (откат к предыдущему набору).
- **Компромисс:** LLM-вызов на генерацию добавляет стоимость и латентность в Tier-0 — учтено в async-модели Tier-0 (ADR-0025: промпты генерируются в фоновой фазе job'а, не в синхронном ответе).
- **Открывает:** отраслевые шаблоны как оптимизацию позже (если авто-ген окажется дорогим/шумным) — не первичный путь.

## Alternatives considered

| Альтернатива | Pro | Contra | Почему отклонили |
|---|---|---|---|
| Только ручной ввод промптов | Просто, точно | Tier-0 (no-auth, мгновенный) так не работает — пришлось бы урезать Tier-0 до Score без Visibility | Tier-0 — первая монетизируемая точка, Visibility нужна |
| Отраслевые шаблоны (библиотека) | Дёшево, предсказуемо | Требует классификацию отрасли; менее релевантно конкретному сайту | Оставлено как поздняя оптимизация, не первичный путь |
| Генерация в P5 (раньше) | Промпты были бы готовы к probe | P5 уже смёржен; gap-анализ (первый массовый потребитель) — в P6 | Реализация там, где первый реальный потребитель |
