# AI-Readiness Score — весовая модель (обоснование)

> Домен: `geo-domain-expert`. Код: [`weights.py`](./weights.py). Версия: `SCORE_VERSION = 1.0.0`.
>
> **Score — сигнал готовности, а не гарантия цитирования.** Веса — доказуемое доменное
> суждение о citation-левелах (AEO/GEO/SEO), детерминированно применяемое к аудит-факторам
> P2. Он НЕ обещает Visibility-% (charter §6.2, honest-forecast). Калибровка весов против
> реальных citation-данных — итерация после P5/P8 (вне scope P3).

## 1. Модель: две линзы воронки цитирования

Цитирование в AI-поиске (ChatGPT/Perplexity/Алиса-Нейро/GigaChat) — двухступенчатая воронка:

1. **Discovery (45 пунктов)** — сайт должен быть *обнаружим и обходим* AI-краулерами.
   Если робот заблокирован или сайт нездоров — цитирование невозможно в принципе (гейт).
2. **Comprehension (55 пунктов)** — обойдённый контент должен быть *понятен* LLM: сущности
   размечены, ответы извлекаемы. Именно эти сигналы решают, попадёт ли сайт в AI-ответ.

Comprehension весит больше: Discovery — необходимое, но не достаточное условие; как только
сайт доступен, реальные citation-левера (schema, FAQ, answer-first) определяют цитируемость.

Сумма всех весов = **100.0** (`TOTAL_WEIGHT`).

## 3. Обоснование по citation-левелам

**Comprehension — первичные левера** (иерархия из PRD §7.2 и role-handbook):

- **`json_ld` (16)** и **`faq` (16)** — доминируют слой (32/55 = 58%). Структурированная
  разметка (Organization/Article/Product/HowTo/FAQPage) даёт LLM машиночитаемые сущности;
  внешние исследования (BrightEdge, ×2.5 шанс AI-ответа при schema; +44% цитирований при
  FAQ/answer-first) — *направленное* свидетельство, не гарантия для конкретного сайта. FAQ и
  answer-first блоки (50–150 слов) — формат, который извлекается и цитируется напрямую. `faq`
  и `json_ld` близки по весу: FAQPage — тип и в JSON-LD, и в answer-first паттерне (overlap).
- **`html_semantics` (10)** — единственный h1, иерархия h2→h3, семантические теги помогают
  ретриверу нарезать релевантные пассажи. Важно, но вторично к явной разметке.
- **`entity_graph` (8)** — @id-связи строят граф знаний; усиливает понимание отношений.
  Пока P2 извлекает только `@type`, не @id-граф → future.
- **`recency` (5)** — свежесть повышает предпочтение источника у LLM; вторичный сигнал, P2
  ещё не извлекает даты → future.

**Discovery — гейт воронки:**

- **`robots_txt` (12)** — старший в слое: явный `Disallow: /` обнуляет цитируемость (жёсткий
  гейт), а отсутствие директив для GPTBot/YandexBot и др. — упущенная возможность.
- **`indexability` (10)** — IndexNow (Bing) и Яндекс.Вебмастер критичны для RU-поверхностей
  (Яндекс/Алиса) и Bing-питаемых (ChatGPT Search, Copilot). deferred до creds.
- **`cwv` (8)** — производительность влияет на приоритет обхода; вторичный discovery-сигнал.
- **`http_status` (8)** — 5xx блокируют индексацию, 4xx дробят краул-бюджет.
- **`sitemap` (7)** — младший: ссылки частично заменяют sitemap для обнаружения.

## 4. Нормировка вердикта → [0..1]

`normalize_verdict(verdict)` (см. `weights.py`):

| Вердикт | Значение | В знаменателе? |
|---|---:|---|
| `pass` | 1.0 | да |
| `warn` | 0.5 | да |
| `fail` | 0.0 | да |
| `deferred` | — | **нет** (исключён) |

**Формула Score** (реализует движок `ScoringEngine`, вне этого файла):

```
scored   = { фактор | is_scored(verdict) }      # pass/warn/fail; deferred исключён
Score    = 100 × Σ(weightᵢ × normalize_verdict(verdictᵢ)) / Σ(weightᵢ)   для i ∈ scored
Score    = 0    если scored пуст (недоступный сайт: audit_summary пуст)
```

- **`deferred` нейтрален, НЕ штраф** (`is_scored` → False): фактор без ключа/экстрактора
  исключается и из числителя, и из знаменателя. Так недоступный сегодня сигнал не занижает
  готовность. Следствие: идеальный сайт с deferred cwv/indexability всё равно достигает 100
  (важно для AC-5 ≥85), а gaming невозможен — `deferred` ставит наш адаптер, не сайт.
- **Граничные свойства:** все scored-факторы fail → Score 0; все pass → Score 100
  (монотонная сепарация; поддерживает AC-5).
- **warn = 0.5** — прозрачный v1-дефолт («на полпути»). Per-factor уточнение warn —
  опция после калибровки (§6), не в scope P3.

## 5. Инвариант §6.5 — `llms.txt` вне Score

`llms.txt` **структурно отсутствует** в `WEIGHTS` — это Integration-layer артефакт (фаза C),
НЕ доказанный citation-рычаг. Score отражает только реальные левера (schema, FAQ, answer-first,
robots, health). Инвариант зафиксирован тройной защитой:

- сторож `EXCLUDED_FROM_SCORE = ("llms_txt",)` (ключ для grep ревьюера и AC-2-теста);
- импорт-тайм `_verify_weight_model()` — `RuntimeError`, если `llms_txt` попал в веса;
- отсутствие фактора в таблице §2.

Тест AC-2: сайт с отличным llms.txt, но плохим FAQ/schema НЕ превышает сайт без llms.txt, но
с хорошим FAQ/schema — выполняется автоматически, т.к. llms.txt не вносит вклад. Добавление
`llms_txt` в веса запрещено без ADR и подписи founder.

## 6. Версионирование

`SCORE_VERSION` (сейчас `1.0.0`) бампится при изменении: значений весов, состава `WEIGHTS`,
или метода нормировки. Смена формулы = **новая версия**, не мутация истории (контракт scoring).
НЕ бампится, когда ранее `deferred` фактор (cwv/indexability по ключу; entity_graph/recency по
экстрактору P6+) начинает приходить со скорируемым вердиктом — это другой вход `audit_summary`,
а не другая модель (детерминизм Score определён относительно входа, FR-1.3 AC-1).
