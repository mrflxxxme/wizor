# WIZOR judge-panel — оптимальность широких форков (ADR-0021 D5 · порт ORIION ADR-037)

Большинство форков — один проход (быстро, дёшево). **Широкий форк** заслуживает judge-панель: сгенерировать N независимых подходов, дать роли `auditor` ранжировать их по фиксированной рубрике, взять победителя и привить лучшие идеи проигравших. Дорогое исследование только там, где окупается.

> WIZOR-нота: судья — `auditor` (Opus, адверсариальный пост-аудит, charter §3/§6), а НЕ отдельный `evaluator` (в лёгком ростере WIZOR роли `evaluator` нет — её функцию несёт `auditor`). Судейство — never-fallback Opus (charter §3.3).

## Когда запускать (критерии широкого форка)

Запускай панель, только если верны **все три**:

1. **Форк agent-owned** (не эскалирован — см. [`escalation-policy.md`](./escalation-policy.md)). Эскалированные форки идут к founder, не к панели.
2. **Пространство решений действительно широкое** — выбор архитектуры / алгоритма / схемы / data-flow, где существуют существенно разные дизайны (не «какое из двух эквивалентных написаний»).
3. **Высокий blast radius** — выбор трудно откатить позже (задаёт схему, полу-публичный шов, кросс-контекстный контракт) ИЛИ доминирует по корректности/стоимости/перформансу фазы.

Любое из трёх ложно → один проход с рекомендованным дефолтом. `planner` флагует широкие форки в `PLAN.md` (`wide_fork: true`), чтобы runner знал вызвать панель.

## Протокол

1. **Генерируй** N независимых подходов (дефолт **N=3**; N=2 для меньших ставок, N=4 для схемы/контракта, который будет очень трудно менять). Каждый подход — холодно (без подглядывания в другие), чтобы они расходились. Подходы генерит релевантный implementer (`backend-implementer`/`frontend-implementer`) или профильный специалист домена, для чисто-дизайнерских форков — `architect`.
2. **Судит** — роль `auditor` скорит каждый подход по рубрике ниже. Refute-by-default: подход должен *заслужить* свой скор.
3. **Выбор + прививка** — берём топ-подход; явно вплетаем любую превосходящую под-идею из проигравших (называем, что привито).
4. **Запись** — `log_decision.py --kind arch` (широкие форки ~всегда архитектурны) с победителем, скорами рубрики и что привито. ADR, если задаёт прецедент.
5. **Эмит evidence** (связка с D3) — прогон панели пишет `evidence/judge_panel_<fork>.json` (verdict `PASS` = победитель выбран с обоснованием; пишет скоры + стоимость). Заявить в `evidence/manifest.json`, чтобы CI-job `evidence` подтвердил: оптимизация реально прогнана против смёрженного коммита — аудируемый след, что «оптимально» не пропущено.

## Рубрика (фиксированный приоритет)

`auditor` ранжирует лексикографически — нижний приоритет ломает тай только среди подходов, равных по верхним:

1. **Корректность** — реально решает задачу, покрывает edge-cases, держит инварианты (напр. Readiness Score детерминирован; Visibility только вне полосы шума N≥5+CI)?
2. **Безопасность / целостность / compliance** — multi-tenant tenant-изоляция, обработка секретов, ПДн-резидентность, read-only-граница, ноль РФ-IP к probe, отсутствие нового attack surface.
3. **Простота / поддерживаемость** — наименьшая концептуальная поверхность, ложится на существующие паттерны (ADR), читаемо через год.
4. **Стоимость** — токен/compute/инфра-стоимость в рантайме + dev-time (уважает `cost-budget.yaml`).
5. **Перформанс** — latency/throughput, только где это важно.

> Корректность, безопасность и **стоячие инварианты §6** — гейты, а не трейд-оффы: подход, проигравший по #1/#2 или ломающий инвариант charter §6, НЕ может выиграть за счёт простоты/скорости.

## Дисциплина стоимости

Панель множит трату токенов на этом форке (~N×). Оправдана только критерием #3 (высокий blast radius). Runner считает трату панели против per-run бюджета (`cost-budget.yaml`, charter §3.4); если бюджет поджимает — деградируй N=3→N=2 до того, как совсем пропустить панель на действительно широком форке.

## Роли

`auditor` (Opus, судья) скорит. N подходов генерят implementer'ы/специалисты или `architect`. Спавн ролей — через `scripts/autonomy/load_role.py --role <role>` (ADR-0020 role-loader), передаётся в `Task`/Agent. Пока role-loader не задействован — панель гоняется in-session (главный агент воплощает роль из `.claude/agents/<role>/system-prompt.md`).
